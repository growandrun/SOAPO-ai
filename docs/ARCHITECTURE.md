# SOAPO 시스템 뼈대

작업치료사의 SOAP 기록과 환자의 가정 재활을 하나의 흐름으로 잇는 서비스의 전체 구조입니다.

## 1. 사용자와 핵심 흐름

| 사용자 | 하는 일 |
|---|---|
| **작업치료사** | 환자 등록 → 평가·목표 입력 → 회기마다 SOAP 작성(AI 초안·점검) → 가정 프로그램 처방 → AI 검진 알림 확인 → 환자와 메시지 |
| **환자·보호자** | 초대 코드로 가입 → 오늘의 운동 수행(카메라·센서 측정) → 통증·소감 기록 → 쉬운 말로 정리된 회복 기록 확인 → 치료사와 메시지 |
| **기관 관리자** | 치료사 면허 확인, 기관 단위 통계 (2단계) |

```
치료사 SOAP (P: 가정 프로그램 처방)
        │
        ▼
환자 앱: 운동 수행 ──카메라/센서──▶ 각도·횟수·통증 기록
        │
        ▼
AI 검진: 수행률↓, 통증↑, 각도↓, 목표 기한, 기록 공백
        │
        ▼
다음 회기 SOAP 초안 (S: 환자 메시지, O: 측정값 자동 채움)
        │
        └──▶ 치료사가 확인·수정·서명  (다시 처음으로)
```

가정 훈련 데이터가 다음 SOAP의 S와 O로 자동으로 들어가, 치료사가 없는 시간의 기록이 치료 과정 안에 남도록 하는 것이 핵심입니다.

## 2. 기술 구성

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | 빌드 없는 정적 웹앱 (`app/`, ES 모듈) | 휴대폰·노트북 브라우저로 접속, 어떤 정적 호스팅에도 폴더째 올릴 수 있음 |
| 로그인 | Supabase Auth 이메일 매직링크 + 6자리 코드 | 비밀번호 없음. 메일을 다른 기기에서 열어도 코드로 로그인 |
| DB | Supabase(PostgreSQL) + RLS + 열 단위 권한 | "담당 환자만" 보이도록 DB가 보장 → `supabase/migrations/` |
| 가입 | DB 함수(RPC) `register_therapist`, `redeem_invite` | 환자는 초대 코드로만 환자 기록과 연결. 클라이언트가 역할을 직접 정할 수 없음 |
| 실시간 | Supabase Realtime (messages 테이블) | 메시지가 새로고침 없이 도착 |
| 카메라 자세 인식 | MediaPipe Pose (브라우저 안에서 처리) | 영상을 서버로 보내지 않아 개인정보 부담이 적음 |
| 라이브러리 | supabase-js를 `app/vendor/`에 고정 버전으로 포함 | 로그인 시점에 외부 CDN에 의존하지 않음 |
| AI | 현재 규칙 기반 (`app/js/ai.js`) → 추후 서버 함수에서 LLM 호출 | 화면 코드는 그대로 두고 교체 가능 |
| 알림 (예정) | 이메일 + 카카오 알림톡 | 운동 알림, 위험 신호 알림 |

> 한국 병원 실제 도입 시에는 국내 리전(Seoul) 호스팅 또는 병원 내부 설치, 병원 EMR 연동(HL7 FHIR)이 필요합니다.

### 권한 요약

| 데이터 | 치료사 | 환자 |
|---|---|---|
| 환자 기본정보 | 담당 환자 읽기·등록·수정 | 본인 읽기 |
| 목표, 평가 점수, 가정 프로그램 | 담당 환자 읽기·쓰기 | 본인 읽기 |
| SOAP 노트 | 담당 환자 읽기·작성, **서명 후 수정·삭제 불가** | 원문 불가, 서명된 최신 평가(A)만 함수로 받음 |
| 가정 수행 기록 | 읽기 | 본인 것만 추가 |
| 메시지 | 담당 환자와 주고받기 | 담당 치료사와 주고받기 (보낸 사람 사칭 불가) |

## 3. 화면 목록

**치료사**
- 환자 목록 (위험/주의 표시)
- 요약·AI 검진: 경고 목록, 목표 기한, 점수 추이, 가정 훈련 수행률
- SOAP 작성: AI 초안 → 실시간 형식 점검 → 서명 (필수 항목이 비면 서명 불가)
- 기록 이력 (서명된 기록은 수정 불가, 정정 기록으로만 보완)
- 가정 프로그램 처방 (카메라 측정 여부 선택)
- 메시지 (AI 답장 초안)

**환자**
- 오늘 할 일: 운동 목록, 카메라로 시작 / 직접 기록
- 내 회복 기록: 점수 변화, 목표를 쉬운 말로 설명
- 치료사와 대화: 위험 증상 자동 감지 후 치료사에게 우선 표시

## 4. AI 기능 설계

| 기능 | 입력 | 출력 | 안전장치 |
|---|---|---|---|
| SOAP 초안 | 지난 노트, 평가 점수, 가정 훈련 기록, 환자 메시지 | S/O/A/P 초안 (빈칸은 `[ ]`로 표시) | `[ ]`가 남으면 서명 불가, AI 사용 여부 기록 |
| 형식 점검 | 작성 중 노트, 직전 노트 | 누락·모호 표현·목표 연결·복사 의심 | 규칙 기반(결정적) + LLM 보조 |
| 자동 검진 | 환자별 최근 데이터 | 위험/주의/정보 알림 | 진단이 아닌 "확인 요청" 형태로만 |
| 쉬운 말 요약 | 서명된 노트, 목표 | 환자용 설명 | 서명된 기록만 사용 |
| 메시지 분류 | 환자 메시지 | 위험/통증/일반 | 위험 시 119 안내 문구 고정 |
| 답장 초안 | 대화, 최근 수행 기록 | 치료사용 초안 | 치료사가 보내기 전 반드시 확인 |

원칙: **AI는 제안하고, 판단과 서명은 치료사가 한다.** 프로토타입의 `AI` 객체는 모두 같은 입출력 형태를 유지한 채 서버 LLM 호출로 교체할 수 있게 나눠 두었습니다.

## 5. 카메라·센서 측정

- 현재: 어깨 굽힘(엉덩이–어깨–팔꿈치 각도)으로 반복 횟수와 최대 각도를 셉니다.
- 추가 후보: 팔꿈치 굽힘/폄, 손목 폄, 앉았다 일어서기, 손가락 집기(MediaPipe Hands), 떨림(가속도 센서)
- 측정값 신뢰도: 카메라 각도는 임상 각도계와 차이가 있으므로 "추이 확인용"으로 표시하고, 병원에서 각도계 값과 비교 검증해야 합니다.

## 6. 보안·법규 체크리스트

- [ ] 개인정보보호법: 건강정보는 민감정보 → 별도 동의, 가명처리, 열람 기록(미구현)
- [x] 의료법: 전자의무기록 무결성 (서명 후 수정·삭제 금지 트리거 적용) / [ ] 보관 기간·백업 정책
- [ ] 의료기기 해당 여부: 진단·치료 판단을 하면 식약처 의료기기 소프트웨어 대상이 될 수 있음 → 1단계는 "기록 보조·재활 관리 도구"로 범위 제한
- [x] 영상은 기기 안에서만 처리, 서버에는 수치만 저장
- [ ] 임상 연구로 효과를 검증하려면 IRB 승인

## 7. 단계별 로드맵

1. **프로토타입 (완료)**: 브라우저 한 파일, 데모 데이터, 규칙 기반 AI
2. **MVP (진행 중)**: Supabase 매직링크 로그인·실제 DB·실시간 메시지 (완료) → LLM 연동, 운동 3종 카메라 측정, 치료사 면허 승인 절차
3. **임상 파일럿**: 교내/협력 병원 치료사 소수 사용, 기록 시간·누락률·가정 훈련 수행률 측정
4. **확장**: EMR 연동, 기관 관리자, 웨어러블 센서, 성과 지표(목표 달성률, K-MBI 변화의 MCID 도달률) 대시보드
